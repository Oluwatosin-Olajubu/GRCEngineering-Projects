# NexusTech Solutions — Security Policy Framework

GRC102 – Information Security Governance, Module 2 / Week 2 practical lab: *Developing Security Policies and Procedures*.

Scenario: I'm the newly appointed Information Security Manager at NexusTech Solutions, a mid-sized ERP company that's grown from 50 to 250 staff and picked up financial and healthcare clients along the way. The company's been running on a single five-year-old "IT Rules" document that mixes policy, technical steps and vague advice together, and CEO Marcus Vance has asked for a proper, structured policy framework. These five files are that framework, built using the Security Policy Development Lifecycle.

## Files in this folder

| File | What it is |
|---|---|
| [`bundle-1-hierarchy.md`](bundle-1-hierarchy.md) | Defines Policy / Standard / Guideline / Procedure, classifies the eight draft statements from the brief, and includes the hierarchy diagram |
| [`bundle-2-aup.md`](bundle-2-aup.md) | The Acceptable Use Policy itself |
| [`bundle-3-access-procedure.md`](bundle-3-access-procedure.md) | The User Access Request Procedure for Helpdesk |
| [`bundle-4-comms-training.md`](bundle-4-comms-training.md) | The rollout plan for getting staff to actually read and follow the AUP |
| [`bundle-5-review-memo.md`](bundle-5-review-memo.md) | A review memo triggered a year later by the AWS migration and a data-handling incident |
